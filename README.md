# 桥 · 多通道聚合

把 **微信 / QQ / 本机 API** 三类通道接入 Operit 对话，统一收发、自动回复回传，并对外提供 OpenAI 兼容网关。

> Operit ToolPkg，API 2.0.0
  
仓库：https://github.com/lihe233/bridge-hub

---

## 它能做什么

| 通道 | 接收 | 发送 | 说明 |
|---|---|---|---|
| **微信** | Python 并发长轮询 | `Tools.Net.http` | 扫码登录，三路 lane 错开 6 秒 |
| **QQ** | WebSocket 长连接 | `Tools.Net.http` | 官方 Bot 协议，支持多账号同时在线 |
| **公开接口** | Python 本地网关 | Python 本地网关 | OpenAI 兼容 `/v1/chat/completions` |

三条通道共用同一套「对话绑定 → 消息注入 → 回复回传」逻辑，一个账号绑定一个 Operit 对话。

### 核心能力

- **扫码登录**：加载微信官方二维码页面，扫完自动保存凭证，无需手动确认
- **正在输入**：由 Python 独立线程发送心跳，长回复期间持续显示不闪烁
- **多账号**：微信、QQ、公开接口均可开多个账号并行运行
- **对话自动重建**：绑定的对话被删掉时自动新建并重新绑定，不丢消息
- **失败重试**：最多重试 2 次，超过即放弃并记录，不会无限循环
- **消息去重**：按 `msg_id` 去重，多路并发不会重复回复
- **回收站**：删除的账号软删除到 `.trash/`，可恢复、可彻底删除

## 安装

1. 在 Operit 插件市场安装，或本地导入 `.toolpkg`
2. 启用主包 `com.operit.bridge_hub` 及两个子包
3. 打开侧边栏「桥」，进入 **通道** 页添加账号

---

## 配置

### 微信

1. 通道 → 微信 → 添加账号
2. 点「扫码登录」，用微信扫页面上的二维码
3. 扫码成功后自动保存，账号变为「轮询中」
4. 点「选择已有对话」绑定一个 Operit 对话

### QQ

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，获取 `AppID` 和 `AppSecret`
2. 通道 → QQ → 添加账号，填入 `AppID` / `AppSecret`
3. 绑定对话

> QQ 机器人需要**两个不同应用**才能多开，同应用的多条连接会被服务端踢掉。

### 公开接口

1. 通道 → 公开 → 添加账号，设置端口（默认 `8789`）
2. 刷新令牌生成 `sk-` 开头的密钥
3. 调用方式：

```bash
curl http://127.0.0.1:8789/v1/chat/completions \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"operit","messages":[{"role":"user","content":"你好"}]}'
```

## 已知限制

- **微信「正在输入」没有时长参数**，服务端硬编码约 3~5 秒，只能靠高频续期维持
- **QQ 没有「正在输入」接口**，官方 API 无此能力
- **微信 `getupdates` 固定挂 18 秒**，这是平台行为；本项目用三路并发错开把最坏延迟压到 6 秒
- **`Tools.Net.http` 是串行的**，一个阻塞请求会堵住后面所有请求；微信长轮询已移至 Python 规避
- **群的普通消息收不到**，QQ 需要 @ 机器人才会推送

## 技术参考

本项目在以下方面参考了现有实现的做法与协议行为，代码为自行编写：

- **微信 iLink 协议**：扫码登录、长轮询 `getupdates`、`sendtyping` 输入状态等接口的调用方式，参考了社区已有微信桥接插件的实现思路
- **QQ 官方 Bot 协议**：`getAppAccessToken` 鉴权、WebSocket `op1` / `op2` 心跳与鉴权、消息回包格式，参照 QQ 开放平台官方文档及社区 Q Bot 模板
- **Operit ToolPkg 开发**：API 2.0 的运行时模型、IPC 通道、工具面注册方式，参考平台自带类型定义与示例包

> 以上仅参考接口调用方式与协议格式，未直接使用他人源代码文件。

本项目不包含任何第三方插件的代码，也不对其做分发或二改。
